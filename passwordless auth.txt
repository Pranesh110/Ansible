Passwordless SSH authentication for Ansible
===========================================

Ansible uses SSH from the control node to connect to managed nodes. Set up an SSH key on the control node and install its public key on each managed node. After that, SSH and Ansible can authenticate with the key instead of asking for the account password.

Assumptions
-----------
- The control node is Linux, macOS, or WSL and has OpenSSH client tools installed.
- Replace "ansible" and "managed1" below with the remote login user and managed-node hostname or IP address.
- The remote user must already exist on each managed node.

One-time setup on the control node
----------------------------------

1. Generate a key pair (run this once for the control-node user that will run Ansible):

   ssh-keygen -t ed25519 -C "ansible-control"

   Press Enter to use the default key location, ~/.ssh/id_ed25519. Set a passphrase if desired; if you do, use ssh-agent to cache it for your session.

2. Copy the public key to each managed node:
Password based setup:
   ssh-copy-id  ansible@managed1

SSH-key based setup:

ssh-copy-id -f "-o IdentityFile pathofpem" ansible@ip

   Enter the password for the "ansible" account on the managed node when prompted. Repeat ssh-copy-id for every managed node, for example:

   ssh-copy-id -i ~/.ssh/id_ed25519.pub ansible@192.0.2.11
   ssh-copy-id -i ~/.ssh/id_ed25519.pub ansible@192.0.2.12

   For an SSH server using a non-default port, specify it with -p:

   ssh-copy-id -i ~/.ssh/id_ed25519.pub -p 2222 ansible@managed1

The remote account password is needed only to install the key. Password authentication must be enabled on the managed node for the initial ssh-copy-id connection. If the account has no password, an administrator must set one on the managed node (for example, run "sudo passwd ansible" there) or use another authorized way to install the public key. Do not put the account password in this file or in source control.

Verify SSH from the control node
--------------------------------

Connect without being prompted for the remote account password:

   ssh ansible@managed1

Then check Ansible connectivity. For example, create an inventory file named inventory.ini:

   [managed]
   managed1 ansible_host=192.0.2.11 ansible_user=ansible
   managed2 ansible_host=192.0.2.12 ansible_user=ansible

Run:

   ansible -i inventory.ini managed -m ansible.builtin.ping

A successful result contains "ping": "pong". The first SSH connection may ask you to confirm the host key; verify the host identity and accept it.

Notes
-----
- Keep the private key (~/.ssh/id_ed25519) on the control node and do not share it. Only the .pub public key is copied to managed nodes.
- This configures SSH authentication only. If Ansible tasks need sudo/root privileges, configure privilege escalation separately (for example, with become: true).
- On Windows, run these OpenSSH commands from WSL or another environment that provides ssh-copy-id.
